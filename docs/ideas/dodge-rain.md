# 极简雨滴 — Idea One-Pager

## Problem Statement
如何用最少的复杂度，做一个让人想多玩几局的 Android 躲避游戏？

## Recommended Direction
竖版单屏躲避游戏。角色在底部通过左右滑动横向移动，障碍物（雨滴/陨石/任意方块）从顶部随机下落，速度随存活时间线性递增。三条命制，碰到一次扣一条命，三条命用完游戏结束，显示本局存活时间作为得分。

选择这个方向的原因：实现路径完全清晰（自定义 View + 游戏循环 + 碰撞检测），没有需要验证的产品假设，每一步都能产出可运行的东西——完全服务于走通 agent-skills 流程这个真实目标。

## Key Assumptions to Validate
- [ ] Android 原生 Canvas 绘图性能足以支撑 60fps 的简单 2D 游戏
- [ ] 手势滑动响应延迟在可接受范围内（< 16ms）
- [ ] 不引入游戏引擎（LibGDX 等）也能在合理时间内完成

## MVP Scope

**In：**
- 自定义 GameView（继承 View 或 SurfaceView）
- 玩家角色：底部横向移动，响应左右滑动手势
- 障碍物：从顶部随机 X 位置生成，匀速下落，速度随时间递增
- 碰撞检测：矩形碰撞（AABB）
- 三条命 UI（顶部显示）
- 计时得分（存活秒数）
- 游戏结束界面（显示得分 + 重玩按钮）

**Out：**
- 音效 / 音乐
- 动画特效
- 本地最高分持久化
- 多种障碍物类型
- 开始动画 / 教程

## Not Doing (and Why)
- **排行榜** — 需要服务端，超出范围
- **音效** — 增加资源管理复杂度，与流程练习目标无关
- **游戏引擎** — 目标是走 Android 原生开发流程
- **多关卡** — 单屏单局足够验证完整流程
- **持久化最高分** — MVP 不需要，可后续加

## Open Questions
- 使用 `View` 还是 `SurfaceView`？（SurfaceView 有独立渲染线程，更适合游戏，但稍复杂）
- 最小 Android API Level 定为多少？（建议 API 24 / Android 7.0）
